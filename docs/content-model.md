# Як додавати матеріали посібника

Вступ — глави 1–5, незалежні від перемикача. Далі: Foundation 6–9, Core 10–13,
Combination 14–17, Advanced 18–22, Challenge 23–26.

## Зміст і зв’язки

- `content/chapters.ts` — назви, порядок, рівні, передумови й навчальні цілі.
- `content/chapter-outlines.ts` — основні групи патернів, додаткові та optional-теми.
  Foundation і Core мають рівно три патерни на главу: по 4 × 3 = 12.
  Prefix Sum і Prefix Count об’єднані на сторінці `/patterns/prefix-sum/`.
- `content/problem-type-groups.ts` — 14 альтернативних маршрутів. `chapterIds`
  посилаються на ті самі глави; не потрібно копіювати контент для другого режиму.
  Зворотні зв’язки на сторінці глави обчислюються автоматично.
- `content/patterns.ts` — наповнені патерни. Чернетки автоматично беруть назви й
  зв’язки з основного змісту. Додаткові теми не стають окремими патернами автоматично.
- `content/tasks.ts` — навчальні й практичні задачі. Зв’язок задається тільки через
  `task.patternIds`; дублювати список задач у патерні не потрібно.
- `content/foundation/` — чотири модулі з матеріалами глав; `helpers.ts` збирає
  однакову структуру уроків без дублювання назв етапів. Тут зберігаються 12 повних
  розборів та 24 основні авторські практичні задачі; XOR-вправа — додаткова extension.
- `content/foundation/preparation/` — базова підготовча теорія та інструменти C++17
  для всіх 12 патернів. Матеріал приєднується за стабільним `pattern.id`.
- `content/theory/` — розширення підготовчої теорії для всіх опублікованих
  патернів Foundation, Core, Combination і Advanced. Воно доповнює `preparation`, не змінюючи
  основний матеріал патерну чи навчальну задачу.
- `content/foundation/extensions.ts` — необов’язкові Prefix XOR, Contribution preview,
  перебір дільників / факторизація та Binary Exponentiation.
- `content/core/` — чотири модулі рівня Core: Two Pointers, Search, Greedy та
  Monotonic Structures. Вони містять 12 патернів, 12 повних навчальних розборів
  і 24 практичні задачі. `core/helpers.ts` зберігає спільний шаблон.
- `components/content/core-visuals.tsx` — інтерактивні навчальні схеми для руху
  меж, binary search, greedy-порядку, інтервалів, stack і monotonic deque.
- `content/combination/` — Graphs, Trees/DSU/MST, Dynamic Programming і Queries.
  Рівень має 12 патернів, 12 навчальних розборів і 36 практичних задач. Основний
  акцент — модель, переформулювання та явна комбінація раніше вивчених технік.
- `components/content/combination-visuals.tsx` — інтерактивні моделі обходу grid,
  вибору shortest path, topological order, Euler Tour, DSU, Kruskal, Grid DP та
  вибору структури для range operations.
- `content/advanced/` — п’ять модулів рівня Advanced: Strings, Geometry,
  Bitmask/MITM, Advanced Graphs/Trees і Math. Рівень має 15 патернів, 15 повних
  авторських розборів і 51 практичну задачу. Для кожного патерну підготовлено
  п’ять великих секцій окремої theory-сторінки.
- `components/content/advanced-visuals.tsx` — 15 інтерактивних покрокових моделей:
  fallback KMP, Z-box, rolling hash, cross product, перетини, hull, маски, MITM,
  декомпозиції графів, binary lifting, rerooting, expectation і matrix power.
- `content/challenge/` — чотири фінальні модулі: Matching/Flow, DP Optimization,
  Game Theory та Reformulation. Рівень має 12 патернів, 12 повних авторських
  розборів і 36 практичних задач із поступовим приховуванням патерну.
- `components/content/challenge-visuals.tsx` — інтерактивні reductions для
  augmenting/residual paths, DP opt windows, CHT, ігор, state expansion,
  reverse time та HLD decomposition.
- `content/final-mixed-set.ts` — фінальний checkpoint із 10 задач без назв
  патернів, рівнів і hints. Він показується наприкінці глави 26 та не входить у
  лічильники практики окремих патернів.

Не змінювати опубліковані `id` і `slug` при перейменуванні матеріалу. Зокрема,
Search Techniques зберігає адресу `/chapters/binary-search/`.
Патерн «2D Prefix» зберігає `/patterns/prefix-xor-2d/`. XOR-контент і вправа
`xor-queries` тепер належать до розширення `prefix-sum`; сам ID вправи збережено.

## Шаблон патерну

Для готового патерну заповнити:

- `description` — яку властивість задачі досліджуємо;
- `intuition` — відкрите пояснення з маленьким прикладом перед задачею;
- `modeling` — системний Combination-блок «Як змоделювати задачу»;
- `priorKnowledge` — короткий місток «Що вже використали з Foundation» для Core;
- `recognitionSigns` — як розпізнати цей патерн в умові;
- `constraintSignals` — які обмеження важливі;
- `notApplicableSigns` — коли алгоритм НЕ підходить;
- `preparation` — необов’язкова підготовка перед задачею: вступ, тематичні секції
  з `ContentBlock[]` і короткі питання з відповідями. Для Foundation заповнена
  всюди: поняття з нуля, приклади C++, таблиці кроків, типові помилки;
- `theory` — узагальнення після власної спроби, з прикладами C++;
- `extensions` — необов’язкові згорнуті розширення після підсумку;
- `hasContent: true` — відкриває посилання та статичну сторінку.

Додати рівно одну готову авторську навчальну задачу. `practiceStatus: 'planned'`
залишається, доки добірка практики не готова. Після додавання 2–4 повних задач
поставити `practiceStatus: 'complete'`. Тести перевіряють цю кількість.
Не створювати фіктивні задачі або URL заради заповнення карток.

Порядок сторінки: основна ідея → посилання на окрему сторінку теорії → інтуїція
та приклад → за наявності «Як змоделювати» → як розпізнати → constraints → коли не підходить →
навчальна задача → підсумок → практика.
«Теорія та C++: заповнити прогалини» є помітним посиланням одразу після
«Основної ідеї» й веде на `/patterns/[slug]/theory/`. На theory-сторінці матеріал
відкритий повністю; згорнутими лишаються тільки відповіді самоперевірки. Глибина
підготовки зростає разом із рівнем: Foundation орієнтовно 1.5–2× від початкового
refresher, Core 2.5–3×, Combination 3–5×. Для Advanced кожна theory-сторінка має
п’ять великих частин: поняття, C++17, механіка, доведення/оцінка та пастки/варіації.
Challenge зберігає цю глибину, але додає явний двосторонній доказ reduction,
перевірку математичних передумов і повну оцінку композиції алгоритмів.
Мініприклади не повинні бути готовим
розв’язком навчальної задачі. Існуючий матеріал після розбору залишається як
«Підсумок та C++ шпаргалка», якір `#theory` збережений.

## Шаблон навчальної задачі

Тип `LearningProblem`: `kind: 'learning'`, `source: 'author'`. Зовнішній URL
заборонено на рівні TypeScript. Умова, вхідні/вихідні дані й constraints видимі
одразу. Далі користувач відкриває по одному кроку; повернення до відкритих кроків
не обмежене. Розкриття — захист від випадкових спойлерів, не приховування даних
у статичних файлах сайту.

Для нової чернетки використовувати `createLearningStages` із
`content/task-template.ts`. Порожні масиви нижче — місця для майбутнього матеріалу,
не готовий урок:

```ts
stages: createLearningStages({
  'try-yourself': [], // Спробуй сам
  hint: [], // Підказка
  'brute-force': [], // Перший підхід (стабільний внутрішній ID)
  'why-slow': [], // Що з ним не так? (стабільний внутрішній ID)
  observation: [], // Ключове спостереження
  algorithm: [], // Алгоритм
  proof: [], // Доведення
  complexity: [], // Складність
  solution: [], // C++ рішення
  takeaway: [], // Що треба запам’ятати
});
```

`ContentBlock` підтримує абзаци, списки, смислові вставки, таблиці, код (`cpp` / `text`)
та схеми (`visual` для Foundation, `core-visual` для Core, `combination-visual`
для Combination, `advanced-visual` для Advanced і `challenge-visual` для
Challenge). Схеми Foundation вбудовані у ключові спостереження, тому
відкриваються разом із відповідним кроком розбору. Компоненти схем не потребують
нових бібліотек; Core-схеми використовують уже наявні React і UI-кнопки. Поле
`examples` містить ввід, вивід і необов’язкове пояснення.
Навчальна логіка розбору: умова → constraints → перший підхід → оцінка →
спостереження → алгоритм → доведення → реалізація. У «Що з ним не так?» можуть
бути час, пам’ять, зайва модель або висновок, що підхід уже оптимальний.
Не вигадувати штучний невдалий brute force. Старі внутрішні ID та поля helper
`bruteForce` / `whySlow` лишено для сумісності, але вони не обмежують зміст етапів.

Задача залишається `status: 'draft'`, поки не готові повна умова та всі кроки.
Для завершеної навчальної задачі встановити `status: 'published'` і
`hasEditorial: true`. Тести перевіряють структуру, а математичну правильність,
однозначність умови й C++ код потрібно перевірити окремо.

## Практичні задачі

- Авторська: `kind: 'practice'`, `source: 'author'`, повна умова всередині картки.
  У Foundation та Core є рівно одна коротка прихована `hint`, приклад і constraints,
  без розбору та готового коду (`hasEditorial: false`, `stages: []`).
- Algotester: `kind: 'practice'`, `source: 'algotester'`. Кнопка
  «Розв’язати на Algotester ↗» з’являється лише з реальним `externalUrl`.
  Якщо авторську практичну задачу згодом розміщено на Algotester, достатньо
  додати їй `externalUrl`: внутрішня умова збережеться, кнопка з’явиться автоматично.
- `status: 'draft'` виключає задачу з публічної добірки.
- `extension: true` позначає необов’язкову практику. У Foundation кожен патерн
  має дві основні вправи; додаткова XOR-вправа не підміняє практику 2D Prefix.

Демонстраційні заготовки Prefix Sum замінені матеріалом користувача:
«Продажі магазину», «Пропущені заняття» та «Сума парних». Адреса патерну збережена.
Позначка Core у чотирьох практичних задачах означає складнішу вправу всередині
Foundation, а не перенесення самого патерну на інший рівень.

## Тренажер «Вгадай патерн»

Тренажер не має окремої копії задач. Він автоматично бере опубліковані задачі з
цього самого каталогу та передає на `/trainer/pattern` лише умову, input/output,
constraints і приклади без пояснень. `hint`, `stages`, доведення та рішення не
входять у trainer-каталог.

За замовчуванням головним вважається перший `patternIds`. Для неоднозначної
задачі або точнішого фідбеку можна додати необов’язкове поле:

```ts
trainer: {
  enabled: true,
  primaryPatternId: 'prefix-sum',
  distractorPatternIds: ['difference-array', 'frequency-counting'],
  explanation: 'Чому цей патерн є головним.',
  signals: ['Сигнал з умови', 'Сигнал з constraints'],
  feedbackByPatternId: {
    'difference-array': 'Чому цей близький варіант тут не підходить.',
  },
}
```

Усі поля необов’язкові. `enabled: false` прибирає задачу з тренажера. Решта
`patternIds`, крім primary, показуються після відповіді як додатково пов’язані
патерни. Якщо ручних distractors недостатньо, тренажер добирає їх із тієї самої
глави, рівня та пов’язаних типів задач.

## Тренажер «Визначте Big O»

Маршрут `/trainer/complexity` використовує окремий типізований каталог
`content/complexity-questions.ts`: ці короткі фрагменти коду й набори constraints
не дублюють умови навчальних задач. Питання мають тип `code` або `constraints`,
4–6 варіантів, одну правильну відповідь, пояснення, зауваження про типову пастку,
difficulty та concept для підсумку помилок.

У змішаному режимі обидва типи потрапляють в один пул. Логіка сесії випадково
обирає до десяти унікальних питань і перемішує відповіді лише під час натискання
«Почати тренування», тому серверний HTML та hydration залишаються стабільними.
Обидва тренажери використовують спільні візуальні компоненти progress і
radio-картки, але мають окрему предметну логіку формування завдань.

## Перевірка

`npm test` перевіряє зміст, зв’язки, шаблони та початковий рендер без спойлерів.
Тести запускаються також у GitHub Actions. `npm run build` перевіряє TypeScript
і статичний експорт. Нових бібліотек для цих змін не потрібно.
